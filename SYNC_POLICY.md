# Sync Policy

This repository is a DSH (DeepSeek Harness) **sibling distribution** of
[Academic Research Skills (ARS)](https://github.com/Imbad0202/academic-research-skills).
The ARS workflow content is vendored from upstream and kept unmodified; only the
outer DSH routing/adapter layer is platform-specific.

## What is vendored

**Byte-identical, no local edits** (1,006 files at this pin):

- `skills/` — the 5 upstream root skill directories, 199 files:
  `deep-research/`, `academic-paper/`, `academic-paper-reviewer/`,
  `academic-pipeline/`, `sr-screener/`.
- `scripts/` — upstream root `scripts/`, 644 files (464 Python helpers,
  checkers, ledger/citation clients, adapters, fixtures, and tests).
- `shared/` — upstream root `shared/`, 155 files (118 JSON schemas/contracts,
  36 Markdown references, 1 YAML file).
- `agents/` — the 4 upstream root agent Markdown files.
- Root files: `MODE_REGISTRY.md`, `THIRD_PARTY.md`, `requirements-dev.txt`,
  `requirements-pdf-content-classifier.txt`.

The source of each skill is the same-named directory at the upstream repository
root, not upstream's `skills/` directory (upstream has no such directory).
These files include each skill's `SKILL.md`, `agents/`, `references/`,
`templates/`, `examples/`, and skill-local `scripts/` as shipped upstream.

**Generated adapter** (do not hand-edit):

- `commands/ars-*/SKILL.md` — 16 wrappers generated from upstream
  `commands/ars-*.md` by `tooling/regenerate-commands.mjs`. The generator adds
  DSH frontmatter (`disable-model-invocation: true`, `user-invocable: true`),
  removes Claude Code-only `Skill` tool and `${CLAUDE_PLUGIN_ROOT}`
  instructions, and adds a package-root note for the vendored core.

**Porting layer** (DSH-specific; may diverge):

- `lib/startup.js` (registration, `resourceBase`, the `DSH_ARS_ROOT` path
  note, and the native tools), `cordis.patch.yml`, `tooling/*.mjs`,
  `native/`, `AGENTS.md`, `docs/agents/`, `README.md`, `NOTICE.md`, package
  metadata, and CI.

**Native layer (0.4.3, released)**: `native/skills/ars-team`, `native/skills/ars-pipeline-team`, the
`ars_search`/`ars_lookup`/`ars_integrity`/`ars_pipeline_status`/`ars_manifest`
tool definitions in `lib/startup.js`, and the `ARS_PRESET` registration for
`agentPresets`. This
is DSH-specific orchestration on top of the vendored ARS roles; it does not
change the vendored files or the 0.3.0 official-recognition baseline.

## Not vendored (current boundary)

The following upstream paths are not included in this distribution:

`audits/`, `docs/`, `evals/`, `examples/`, `hooks/`, `pi/`, `plugin-evals*`,
and upstream root package/release metadata (`package.json`, `pyproject.toml`,
`CITATION.cff`, `CHANGELOG.md`, `CONTRIBUTING.md`, `GOVERNANCE.md`, `LICENSE`,
`NOTICE.md`, `POSITIONING.md`, `QUICKSTART.md`, `README*.md`, `SECURITY.md`).

The runtime content referenced by the skills — `scripts/`, `shared/`, root
`agents/`, and `MODE_REGISTRY.md` — is vendored. `docs/DATA_FLOWS.md` is a
documentation-only cross-reference from one reviewer skill; it is not needed to
execute the workflows. Python dependencies are declared in the vendored
`requirements-dev.txt` (and the optional `requirements-pdf-content-classifier.txt`).

## Sync cadence

ARS ships minor releases roughly every six weeks. The maintainer:

1. Watches upstream tags/releases and opens a GitHub issue for the sync.
2. Checks out the target commit in a clean upstream worktree.
3. Runs `node tooling/sync-upstream.mjs <upstream-checkout>`.
4. Reviews the diff. A core skill file may change only because upstream changed;
   if a local edit is needed, it belongs in the porting layer, not `skills/`,
   `scripts/`, `shared/`, or `agents/`.
5. Runs `npm run verify`, the Python syntax check, and the package-contents check.
6. Runs the DSH smoke test (currently 23 registrations). Before requesting
   official sibling recognition, runs the end-to-end `academic-pipeline`
   evidence run.
7. Updates the package version and release notes, commits, and tags `vX.Y.Z`.

## Drift check

CI (`.github/workflows/verify-vendor.yml`) runs `node tooling/verify-vendor.mjs`
on every push to `main` and every pull request. It fails on any missing, extra,
or modified vendored file (skills, core directories, root core files, and
generated commands), and on a registration count other than 22. The check is
offline and deterministic; it does not need the upstream checkout.

## Versioning and releases

- Package versions are independent of ARS versions (`0.3.0`, `0.4.3`, ...).
  `0.3.0` is the official-recognition baseline; `0.4.3` adds the native layer.
- The README and release notes state the ARS version; `manifest.json` records
  the exact commit.
- Release tags are immutable. Do not move a tag to re-sync content; publish a
  new version.

## Official sibling recognition

Before requesting recognition in the upstream README, this repo must also
provide, per `CONTRIBUTING.md`:

- a full `academic-pipeline` run under `examples/dsh/` (end-to-end evidence);
- claims-evidence alignment for README claims about coverage;
- a model-portability note (which models were tested, what is model-dependent);
- an upstream design issue opened before the recognition request.
