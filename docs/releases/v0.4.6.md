# v0.4.6 — Scope native reads to the DSH session workspace

Addresses [DSH Plugin Index #577](https://github.com/polang233/dsh-plugin-index/issues/577#issuecomment-7034741304).

- `ars_pipeline_status` and `ars_integrity` authorize reads against the calling DSH Session's recorded workspace. Relative arguments still resolve from that Session's current directory; the current directory does not grant access. Missing authorization and out-of-workspace targets are rejected.
- Status omits linked entries; integrity rejects links in paths the vendored checker can inspect. This is a workspace path policy for a stable tree, not an OS read sandbox.
- The [isolated DSH verification](../native-validation.md#workspace-read-boundaries-046) exercised both tools in a real headless session on macOS with DSH `0.2.2-rc.5`, using fixed local model responses. Both accepted the authorized fixture and rejected the ungranted fixture. Offline boundary regressions are part of CI.

The ARS pin (`6d93886`), vendored content, and existing E2E artifacts are unchanged. The paper E2E was not rerun.
